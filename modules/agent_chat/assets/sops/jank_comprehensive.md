## 概述

综合卡顿分析通过三个维度交叉关联定位卡顿根因：

1. **Trace 分析**：精确定位丢帧时间点和直接原因（主线程耗时、渲染管线阻塞、Binder 调用等）
2. **PerfDog 分析**：宏观性能指标（FPS 波动、Jank 率、内存/功耗趋势）
3. **策略审查**：当前性能策略配置是否合理（CPU/GPU 频率策略、场景识别、温控策略）

三者结合可以回答：**卡顿发生在哪里、为什么卡、当前策略能否解决、该如何调整**。

## 前置条件

- Perfetto trace 文件（.perfetto-trace）
- PerfDog 导出报告（.xlsx），与 trace 同时段采集
- 设备上的 gameperfconfig.xml（可通过 ADB pull 或手动提供）
- 三份数据应来自**同一次测试**

## 分析步骤

### 步骤 1: 创建分析工作目录

调用 `create_workspace` 创建本次分析的工作目录，后续报告和中间文件将存放于此。

### 步骤 2: 收集分析文件

向用户收集三份文件路径：
1. Perfetto trace 文件路径
2. PerfDog xlsx 报告路径
3. gameperfconfig.xml 配置文件路径

如果用户只有部分文件，可以先进行可用数据的分析，最后说明哪些维度缺失。

### 步骤 3: Trace 丢帧分析

调用 `pa_analyze` 执行完整 trace 分析：
- 提取丢帧数量、丢帧率
- 各维度分析结果（主线程耗时、渲染管线、Binder、CPU 频率、GPU 频率、调度延迟）
- 记录 **丢帧高发时间段** 和 **主要丢帧原因**

### 步骤 4: PerfDog 性能分析

调用 `pdi_load_report` 加载报告，再调用 `pdi_summarize` 汇总：
- FPS 统计（均值、最低、P1）
- Jank/BigJank 比率
- 内存使用峰值
- 功耗平均值
- 记录 **性能瓶颈指标**

### 步骤 5: 策略配置审查

调用 `gp_analyze_config` 解析配置：
- CPU/GPU 可用频点
- 目标游戏的场景策略
- 温控策略
- 记录 **当前策略配置**

### 步骤 6: 交叉关联分析

将三个维度的结果交叉比对：

| 丢帧原因 | PerfDog 表现 | 策略是否覆盖 | 建议 |
|---------|-------------|------------|------|
| 主线程 CPU 耗时 | FPS 波动/低 P1 | 查看 CPU 频率策略 | 提升 CPU 频率下限 |
| GPU 渲染管线阻塞 | 渲染帧耗时高 | 查看 GPU 频率策略 | 提升 GPU 频率 |
| Binder 跨进程延迟 | N/A | 查看调度策略 | 优化 Binder 优先级 |
| 调度延迟/抢占 | Jank 率高 | 查看核心绑定策略 | 调整任务亲和性 |
| 内存压力 | 内存峰值高 | N/A | 优化内存使用 |

### 步骤 7: 输出综合结论

按以下结构输出分析报告：

1. **问题列表**：按严重程度排序的卡顿问题
2. **原因归因**：每个问题的根因分析
3. **策略评估**：当前策略的覆盖度和有效性评价
4. **调整建议**：具体的策略调整参数（新旧值对比 + 调整理由）

## 输出规范

综合报告应包含：
- 测试环境信息（设备型号、游戏版本、测试场景）
- 关键指标汇总表
- 逐项问题分析
- 策略调整建议（含具体参数值）
