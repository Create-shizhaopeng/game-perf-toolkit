## 设计约束

- Agent Tab 位于主窗口 **第一个 Tab**（最左侧），与架构文档 §8.1 一致
- 继承 `BaseTab`，使用项目统一的暗色/亮色主题（Catppuccin 风格）
- 不依赖设备连接状态（Agent 可独立工作）
- 流式输出：Agent 文本回复逐步渲染（打字机效果）
- **无手动 SOP 下拉选择器**——Agent 根据用户意图自动匹配 SOP（C-006）
- 工具调用过程可视化展示

│              │   （消息区域 — QScrollArea）                │
│ ● 今天       │                                           │
│  [新建对话]  │   ... 对话消息 / 工具调用卡片 ...          │
│  └ 卡顿分析  │                                           │

## 左侧面板

### 会话历史

按日期分组显示历史对话记录，每条显示对话标题（取自首条用户消息前 20 字）。

```
┌── 会话历史 ───── [+ 新建对话] ──┐
│                                │
│ ● 今天                         │
│  ├ 🔵 分析游戏卡顿问题          │  ← 当前会话（高亮）
│  └ ⚪ 策略配置审查              │
│                                │
│ ● 昨天                         │
│  ├ ⚪ Trace 分析 #3            │
│  └ ⚪ PerfDog 联合分析          │
│                                │
│ ● 3月22日                      │
│  └ ⚪ 首次测试对话              │
│                                │
└────────────────────────────────┘
```

**交互说明**：
- 点击历史对话：右侧聊天区加载该会话的完整消息记录（只读回看 + 可继续对话）
- 当前活跃会话蓝色高亮标记
- 右键菜单：重命名、删除
- 新建对话按钮（`+`）：清空右侧聊天区，开始新会话
- 会话列表使用 QListWidget + QScrollArea，支持滚动

**数据存储**：SQLite `agent_chat.db`，表 `conversations`（id, title, created_at, updated_at）和 `messages`（id, conversation_id, role, content, tool_calls, created_at）

### SOP 管理

底部区域显示 SOP 文档列表，分为内置和自定义两组。

```
┌── SOP 管理 ─────────────────────┐
│                                 │
│ 📁 内置 (4)                     │
│  ├ 📄 Trace 分析                │
│  ├ 📄 PerfDog 分析              │
│  ├ 📄 策略审查                   │
│  └ 📄 综合卡顿分析               │
│                                 │
│ 📁 自定义 (2)                    │
│  ├ 📄 Trace+PerfDog 联合        │  ← 用户保存的工作流
│  └ 📄 快速性能检查               │
│                                 │
│ [📥 导入]  [📋 管理]             │
│                                 │
└─────────────────────────────────┘
```

**交互说明**：
- 双击 SOP 条目：在右侧聊天区显示该 SOP 的内容预览（只读）
- 右键菜单（自定义 SOP）：编辑（调用系统默认编辑器打开 .md 文件 C-008）、删除、导出
- 右键菜单（内置 SOP）：查看（只读）
- **导入按钮**：打开文件选择器，导入外部 Markdown SOP 到 `data/sops/`
- **管理按钮**：打开 SOP 管理弹窗（见设置面板章节）

无 API Key 时，消息区域显示配置引导卡片（替代欢迎消息）：

```

│                                                      │
│  🔑 需要配置 AI 模型才能开始使用                      │
│                                                      │
│  Provider:  ○ GLM (智谱)    ○ Claude (Anthropic)    │
│  API Key:   [________________________________]       │
│                                                      │
│  💡 GLM 推荐国内用户使用，Claude 推理能力更强         │
│                                                      │
│                        [保存并开始对话]                │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### SOP 自动发现与渐进式披露

**交互流程**：

```
用户: "帮我分析一下游戏卡顿问题"

Agent: 已识别任务类型。我将按以下工作流进行分析：

  ┌── 📋 工作流: 综合卡顿分析 ──────────────────────┐
  │                                                  │
  │  Step 1: 📁 收集分析文件                         │
  │  Step 2: 🔍 Trace 分析（丢帧检测 + 归因分析）     │
  │  Step 3: 📊 PerfDog 数据分析（性能指标）          │
  │  Step 4: ⚙ 策略配置审查                          │
  │  Step 5: 📝 综合研判 + 策略建议                   │
  │                                                  │
  └──────────────────────────────────────────────────┘

  首先，请提供以下文件：
  • Perfetto trace 文件（.perfetto-trace）
  • PerfDog 导出数据（.xlsx）[可选]
  • 当前策略配置（gameperfconfig.xml）[可选]

  你可以直接拖放文件到输入框，或输入文件路径。
```

**多 SOP 候选时**：

```
用户: "看看性能有没有问题"

Agent: 有以下几种分析方式可供选择：

  1️⃣ Trace 分析 — 从 Perfetto trace 检测丢帧原因
  2️⃣ PerfDog 分析 — 从 PerfDog 数据分析 FPS/内存/功耗
  3️⃣ 综合卡顿分析 — 结合 Trace + PerfDog + 策略配置

  请选择一种，或直接告诉我你有什么数据。
```

### 工具调用可视化

工具调用以可折叠卡片形式内嵌在 Agent 消息中：

**执行中**：

```
  ┌─ 📎 pa_analyze ──────────────────────────────────┐
  │ trace_path: D:/traces/game_001.perfetto-trace    │

**完成**：

```
  ┌─ 📎 pa_analyze ─────────────── ✅ 完成 (12.3s) ─┐

### 历史报告访问

分析工具产生的报告（Markdown/目录）可在对话中直接访问：

**在工具完成卡片中**（见上方"📂 打开报告目录"）

**在 Agent 回复中**：

```
Agent: 分析完成。完整报告已生成：

  📄 output/trace_report/game_001/report.md
     [📂 打开目录]  [📋 查看报告]

  📄 output/trace_report/game_001/dimensions/
     [📂 打开目录]
```

**交互说明**：
- **打开目录**：调用 `os.startfile()`（Windows）在资源管理器中打开
- **查看报告**：在对话中内嵌展示 Markdown 报告内容（折叠/展开），或在系统默认 Markdown 查看器中打开
- 历史对话中的报告链接始终可点击（路径持久化）

**从历史会话回看报告**：
- 点击左侧会话历史条目 → 加载该会话消息 → 工具结果卡片中的"打开报告"链接仍然可用
- 如果报告文件已被删除，显示"报告已不存在"灰色提示

| 配置引导 | 居中 | 卡片表单 | `#313244` |

## 输入区域

- **QTextEdit** 多行输入，高度自适应（1-5 行）
- **Enter** 发送，**Shift+Enter** 换行
- 右侧 **发送按钮**（圆角，主题色 `#cba6f7`）
- Agent 响应期间：输入框禁用 + 发送按钮变为**停止按钮**（红色，允许中断当前 LLM 调用）
- 支持拖放文件到输入区域，自动在文本末尾追加文件路径

## 停止与中断行为

Agent 正在响应时，发送按钮变为红色**停止按钮**（C-011）。

### 停止按钮行为

```
┌── 停止后的 UI 状态 ──────────────────────────────────┐
│                                                      │
│  Agent: 正在分析 trace 文件...                        │
│                                                      │
│  📎 pa_analyze                                       │
│  ┌──────────────────────────────────────────┐        │
│  │ ⛔ 已取消                                │        │
│  └──────────────────────────────────────────┘        │
│                                                      │
│  ⚠️ 工作已中断，工作区域已清空。                       │
│  你可以开始新的对话。                                  │
│                                                      │
├──────────────────────────────────────────────────────┤
│  [输入消息...                                ] [发送] │
└──────────────────────────────────────────────────────┘
```

- 点击停止后立即取消：当前工具执行 + LLM 调用 + 清空临时工作区
- 已产生的部分结果不保留
- 输入框恢复可用状态
- 对话历史中保留到中断点的消息（标记为"已中断"）

## Token 用量展示

每次 Agent 回复后，在消息底部以灰色小字展示 token 统计（C-014）：

```
Agent: 分析完成。以上是完整结果...

                    ───────── 本次: ↑1,234 ↓2,567 tokens ──────────
                    ───────── 会话累计: ↑5,678 ↓12,345 | 预估 ¥0.15 ──
```

- `↑` = input tokens（用户消息 + 工具结果 + system prompt）
- `↓` = output tokens（Agent 回复 + 工具调用）
- 费用预估按模型单价自动计算（GLM: ¥0.1/千tokens, Claude: ~$3/M tokens）
- 可在设置中关闭展示

## 多会话管理

支持多个并行会话（C-009），但同一时刻只有一个会话活跃执行。

### 会话状态标记

左侧面板中每个会话条目有状态标记：

```
┌── 会话历史 ───── [+ 新建对话] ──┐
│                                │
│ ● 今天                         │
│  ├ 🔵⚡ 卡顿综合分析           │  ← 当前会话 + 正在执行
│  ├ 🔵  策略配置审查             │  ← 当前选中（可查看）
│  └ ⚪  Trace 分析 #2           │  ← 历史会话
│                                │
└────────────────────────────────┘
```

- `🔵` = 当前选中查看的会话
- `⚡` = 正在活跃执行（LLM 或工具运行中）
- `⚪` = 非活跃历史会话

### 切换会话时

- 若当前会话正在执行：弹出确认"当前有任务在执行中，切换会话？"
  - 确认切换：自动停止当前执行（同停止按钮行为）
  - 取消：留在当前会话
- 若当前会话空闲：直接切换，右侧聊天区加载目标会话的历史消息
- 切换后可在目标会话中继续发送新消息
