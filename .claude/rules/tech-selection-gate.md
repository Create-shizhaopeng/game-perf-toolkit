
# 技术选型门禁

## 触发条件

在以下场景中 MUST 进行第三方方案评估：

1. 需要实现**与外部服务通信**的功能（API 调用、SDK 封装、协议处理）
2. 需要实现**通用基础设施**（日志、缓存、队列、ORM、序列化等）
3. 从其他模块**迁移代码**到框架层时
4. 需要**自行解析**复杂数据格式（SSE、JWT、Protocol Buffer 等）

## 评估流程

在 Speckit research 阶段，MUST 在 `research.md` 中包含：

```markdown
## 第三方方案评估

| 方案 | 优势 | 劣势 | 适配成本 |
|------|------|------|---------|
| 自建 | ... | ... | ... |
| <候选库1> | ... | ... | ... |
| <候选库2> | ... | ... | ... |

**决策**: [选择方案] — [原因]
```

## 评估维度

- **社区活跃度**: GitHub stars、最近更新时间、Issue 响应速度
- **依赖重量**: 安装体积、传递依赖数量
- **API 稳定性**: 版本发布频率、Breaking changes 历史
- **功能覆盖度**: 是否覆盖当前和可预见的未来需求
- **维护成本对比**: 自建需要多少代码，第三方需要多少适配代码
