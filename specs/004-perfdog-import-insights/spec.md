## User Scenarios & Testing *(mandatory)*

### User Story 1 - 拖拽导入并生成摘要报告 (Priority: P1)

性能测试人员将 PerfDog 导出的数据文件拖入工具指定区域（或等价选择文件入口），工具在合理时间内完成解析，并展示一份**面向阅读的摘要报告**：会话基本信息（应用、设备、时长）、帧率与稳定性结论、温度与功耗概况、明显异常时段数量。

**Why this priority**: 无导入与摘要则后续分析无数据基础；单独交付即可形成可用的「一眼结论」。

**Independent Test**: 仅启用导入与摘要：拖入一份标准 PerfDog Excel 导出，确认报告在 30 秒内呈现且无崩溃。

**Acceptance Scenarios**:

1. **Given** 工具已打开且支持该入口，**When** 用户拖入一份结构完整的 PerfDog Excel 导出，**Then** 工具识别成功并展示摘要报告（含会话元数据与核心指标汇总）。
2. **Given** 用户拖入非 Excel 或明显非 PerfDog 导出，**When** 释放文件，**Then** 工具给出明确错误说明，不覆盖上一份有效结果（或提供清除/重新导入路径）。

---

### User Story 2 - 掉帧 / 帧不稳 / 高温的自动标注与解释 (Priority: P2)

在摘要基础上，工具自动标出：**掉帧或长帧集中时段**、**帧率波动异常**、**温度或热状态异常升高**（以导出文件中可用字段为准），并用**非实现细节**的语言说明「可能成因类别」（例如：开局加载期、偶发尖刺、持续高负载、散热/环境相关提示等），避免断言未在数据中体现的根因。

**Why this priority**: 用户核心诉求是从频点、线程与帧数据中定位「问题类型」，而非只看平均数。

**Independent Test**: 使用已知含开局低帧与中段尖刺的样例文件，报告中应出现分段描述与对应指标引用（时段或占比）。

**Acceptance Scenarios**:

1. **Given** 已成功导入有效文件，**When** 用户查看「问题与洞察」区域，**Then** 至少分别给出与掉帧/帧不稳/温度相关的条目（若数据中缺某项则标注「本文件未包含该项」）。
2. **Given** 数据中存在可识别的长帧或低 FPS 时段，**When** 用户展开对应条目，**Then** 可看到与时间或采样序号相关的定位信息，便于对照游戏内场景。

---

### User Story 3 - CPU/GPU 频点与线程数据的关联洞察 (Priority: P3)

当导出包含 CPU 各核频率、GPU 频率与占用、线程 CPU 使用等字段时，工具在**异常时段附近**给出对比：频点是否处于低位平台、GPU 占用是否持续偏高、线程表中是否存在异常突出的线程（按导出中的线程维度展示，不依赖外部符号）。

**Why this priority**: 增强「为什么当时可能卡」的可解释性；依赖导出列完整性，故列为 P3。

**Independent Test**: 使用含 `@ThreadCpuUsageData` 与频点列的样例，报告中出现「异常时刻前后」的对比小节或表格。

**Acceptance Scenarios**:

1. **Given** 文件包含频点相关列，**When** 用户查看关联分析，**Then** 工具列出异常时段前后窗口内的频点/占用摘要（如均值、是否明显低于前后段）。
2. **Given** 文件不包含线程表或列为空，**When** 用户打开关联分析，**Then** 工具明确提示不可用，不展示误导性空白结论。

---

### User Story 4 - 建议方案（可执行检查清单）(Priority: P2)

基于报告中的**已观察到现象**，工具输出分组建议：例如测试复现条件（画质/帧率/室温/电量）、下一步采集建议（是否需要系统级跟踪）、游戏设置与场景标注习惯、以及何时需要硬件/驱动侧排查。建议须标注**推断性质**（「建议复测验证」），不得伪装为确定诊断。

**Why this priority**: 用户明确要求「建议方案」；与问题条目同级交付才有闭环。

**Independent Test**: 对高温与尖刺两类样例，建议列表内容应有差异且与报告结论一致。

**Acceptance Scenarios**:

1. **Given** 报告判定存在明显尖刺型掉帧，**When** 用户查看建议，**Then** 至少包含与场景标注、复测时段裁剪相关的可操作项。
2. **Given** 报告判定温度或热相关指标持续偏高，**When** 用户查看建议，**Then** 至少包含与环境、散热、复测条件控制相关的可操作项。

---

### User Story 5 - 双会话对比（A/B）(Priority: P3)

用户在同一工具内载入**两份** PerfDog 导出（例如优化前后、不同画质、不同 ROM），工具生成**并列对比视图**：会话元数据差异、核心指标差异（平均帧率、稳定性指标、温度/功耗摘要等），并对「哪一份更差/更好」给出**基于选定指标的客观对比**，不替代业务结论。

**Why this priority**: 研发闭环常见「前后对比」；实现复杂度高于单文件，故列为 P3。

**Independent Test**: 两份同一应用、不同时长的样例均可导入后进入对比模式，对比页无崩溃且差异字段可读。

**Acceptance Scenarios**:

1. **Given** 用户已导入会话 A，**When** 用户通过「添加对比文件」载入会话 B（结构与 A 兼容），**Then** 工具展示 A/B 对比摘要，并标明**不可对比项**（如包名不一致、缺失列）。
2. **Given** 两份文件包名或应用不一致，**When** 用户尝试对比，**Then** 工具提示「应用不一致，对比可能无意义」并允许用户选择仍继续或取消。

---

### User Story 6 - 报告导出与复制 (Priority: P2)

用户可将当前**摘要 + 问题与洞察 + 建议**导出为至少一种可分享格式（如纯文本/Markdown 或等价），并支持一键复制全文，便于贴到邮件、缺陷单或 wiki。

**Why this priority**: 与 FR 升级一致，便于协作与留档；优先级与「建议方案」同级。

**Independent Test**: 导出文件用外部编辑器打开，结构与屏幕报告章节一致；复制后粘贴无乱码（中文与数字）。

**Acceptance Scenarios**:

1. **Given** 已生成完整报告，**When** 用户点击「导出报告」，**Then** 用户获得本地文件且含会话信息、主要指标、发现项与建议章节。
2. **Given** 已生成完整报告，**When** 用户点击「复制报告」，**Then** 剪贴板内容与界面展示一致（允许省略图表像素图，但文字完整）。

---

### User Story 7 - 与 Toolkit（lv-game-toolkit）集成入口 (Priority: P2)

在 **Toolkit 桌面应用**内提供独立入口（例如新选项卡「PerfDog 分析」），复用拖拽导入、报告与对比能力；与现有「设备连接」类选项卡**互不阻塞**（未连接设备亦可仅做离线文件分析）。

**Why this priority**: 与现有工作流统一，减少多工具切换；不依赖 ADB 即可使用本功能。

**Independent Test**: 在无设备连接时打开该入口，拖入 Excel 仍可出报告。

**Acceptance Scenarios**:

1. **Given** Toolkit 已启动，**When** 用户切换到 PerfDog 分析入口，**Then** 可见拖拽区与上次报告状态（或空状态引导），且其他 Tab 行为不变。
2. **Given** 用户在游戏策略等 Tab 中工作，**When** 切换至 PerfDog 分析，**Then** 不自动清除已导入的 PerfDog 会话（除非用户主动清除或关闭应用），行为在界面有说明。

---

### User Story 8 - 解析过程可见与清除会话 (Priority: P1)

导入大文件时用户能看到**进行中状态**（进度百分比或阶段说明或不确定进度指示），避免误以为卡死；用户可随时**清除当前分析**（清空报告与内存中的会话数据），回到可重新拖入的空状态。

**Why this priority**: 与 P1 导入同属基础体验；无清除则误导入后难以恢复。

**Independent Test**: 拖入大文件时出现加载指示；点击「清除」后拖拽区恢复空态且再次导入另一文件成功。

**Acceptance Scenarios**:

1. **Given** 用户拖入大体积 Excel，**When** 解析尚未完成，**Then** 界面显示加载中且主要按钮处于合理禁用或队列状态，解析结束后自动展示报告。
2. **Given** 已展示报告，**When** 用户点击「清除当前分析」，**Then** 报告与对比状态被清空（或回到引导页），无残留敏感路径展示（若设置不记忆路径）。

---

### Edge Cases

- 导出文件过大导致解析超时或内存压力：应提示用户「文件过大」并建议截取时段或更换导出选项，而非静默失败。
- 部分 PerfDog 版本列名或表结构差异：应尽力映射已知列；无法映射时列出「未识别列」而非崩溃。
- `Data_v4` 表头不在固定行：应支持在合理范围内探测表头行或提示「无法定位数据表」。
- 用户连续拖入多个文件：**默认**更新当前主会话（覆盖上一份摘要）；若用户已固定「会话 A」并处于对比流程，第二次拖入应明确是「替换 A」「设为 B」还是「取消」，避免误覆盖。
- 两份文件体量均很大：对比模式应提示等待或分阶段加载，避免界面假死。
- 隐私与安全：报告界面避免默认收集路径外的个人信息；文件仅本地处理（除非产品另有云同步范围，本 spec 默认本地）。
- **受保护/加密工作簿**或 **非 .xlsx/.xlsm 且无法按 Open XML 解析**：应提示「无法打开」而非崩溃；**宏工作簿（.xlsm）**若支持打开，MUST 不执行宏内容（仅数据读取）。
- **导出失败**（磁盘满、无写权限、路径非法）：须明确错误原因，保留屏幕报告不丢失。
- **设备名等元数据乱码**：因 Excel/编码导致中文显示异常时，报告仍须展示原始单元格字符串或十六进制可读摘要之一，并可在附录说明「与源文件编码一致」。
- **汇总行与序列不一致**：`all` 表中 Stat 汇总与 `Data_v4` 自行计算结果差异超过实现约定阈值时，报告中可标注「以序列重算为准 / 或以 PerfDog 汇总行为准」之一，避免用户困惑（具体策略在实现计划中二选一并写清）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 工具 MUST 支持通过拖拽（及等效文件选择）导入 PerfDog 导出的 Excel 格式数据文件。
- **FR-002**: 工具 MUST 解析导出中的时间序列数据（含帧率、平滑度/卡顿相关指标、抖动或 Jank 相关指标，以文件中可用字段为准）；当存在 **`@FrameInfo`**（或等价逐帧时长表）时，MUST 将帧时长分布摘要（如长尾帧占比、最大帧时刻）纳入「问题与洞察」或附录，并与秒级结论交叉引用（若两者时间轴可对齐）。
- **FR-003**: 工具 MUST 解析并汇总设备与应用会话元数据（如包名、机型、采集起止、时长），并在报告中展示。
- **FR-004**: 工具 MUST 在存在数据时，识别并描述：**显著低帧或长帧时段**、**帧率稳定性异常**（如方差/百分位或等价指标）、**温度或热相关指标异常**（以导出字段为准）；当导出含**功耗、电流、电压、电量**等列时，MUST 在摘要或洞察中给出与异常时段相关的**可选段落**（缺失列则跳过，不留白结论）。
- **FR-005**: 当导出包含 CPU 频点、GPU 频率与 GPU 占用等列时，工具 MUST 在异常时段附近提供这些指标的对比摘要。
- **FR-006**: 当导出包含线程 CPU 使用表时，工具 MUST 能按异常时段对齐，展示相对突出的线程维度（列名/线程名以导出为准），并说明局限性（无符号、可能聚合误差）。
- **FR-007**: 工具 MUST 基于已识别现象生成**分组建议**，且建议与现象一一可追溯（用户可从建议跳回或对照相关指标段落）。
- **FR-008**: 工具 MUST 对所有推断性结论使用明确措辞（如「可能与…相关」「建议复测确认」），禁止将启发式输出表述为唯一根因。
- **FR-009**: 工具 MUST 对不支持、损坏或空文件给出可理解的错误信息，并维持界面可恢复状态。
- **FR-010**: 工具 MUST 支持**导出**报告为本地文件（至少一种通用文本类格式，如 Markdown 或 UTF-8 文本），并 MUST 支持**一键复制**报告全文。
- **FR-011**: 工具 SHOULD 支持**两份**会话的并列对比；对比维度至少包含：会话元数据、核心帧率与稳定性汇总、温度/功耗（若存在）；对缺失列须标注「仅单侧有数据」。
- **FR-012**: 当两份会话应用标识不一致时，工具 MUST 显式警告并需用户确认后方可展示对比结果。
- **FR-013**: Toolkit 集成形态下，工具 MUST 提供独立入口完成 **MVP 用户故事**（至少 **US1、US8、US2、US4、US6、US7** 及其对应功能需求）；**不得**要求设备已连接才能完成文件导入与分析。**US3、US5**（频点/线程深化与 A/B 对比）可在后续里程碑补齐（见实现计划）。
- **FR-014**: 工具 SHOULD 在集成入口中持久化「最近一次导入路径或会话标识」（若隐私策略允许），以便用户刷新界面后快速识别；不得在未授权时上传路径至网络。
- **FR-015**: 工具 MUST 在解析或重计算耗时超过 **3 秒**（可配置阈值，产品默认 3s）时显示**非阻塞或阻塞式加载指示**（至少一种），且 MUST 提供**清除/取消本次导入**的路径（若技术可行则中断后台任务；若不可行则提示「请等待完成或关闭应用」）。
- **FR-016**: 工具 MUST 提供「**清除当前分析**」能力：清空当前会话、对比中的 B 侧（若有）及界面展示，且不静默保留不可见的巨型缓存（除非用户明确开启「保留以便对比」类选项，该选项为 SHOULD）。
- **FR-017**: 工具 MUST **无需网络**即可完成导入、分析、导出与复制（本 spec 范围内不调用远程 API）。
- **FR-018**: 工具 SHOULD 在报告末尾或帮助区提供**简短说明**：本工具使用的**异常判定维度**（如低帧、尖刺、温度、频点等）及「结果为启发式」提示，便于与 PerfDog 官方指标对齐理解；**不要求**首期开放用户自定义全部阈值。
- **FR-019**: 导出文件 MUST 使用 **UTF-8** 编码（带 BOM 或不带 BOM 由实现选定，须在导出说明中一致）；复制到剪贴板 MUST 使用 Unicode 文本，避免中文乱码。

### Key Entities *(include if feature involves data)*

- **PerfDog 会话 (SessionSummary)**：应用标识、设备标识、采集时间范围、总时长、数据版本或工具版本（若存在）。
- **时间序列采样 (MetricSample)**：时间戳或序号、帧率、帧时间或平滑度、CPU/GPU 频点与占用、温度与功耗、热状态等（以实际列存在为条件）。
- **帧级记录 (FrameSample)**：帧时间等逐帧数据（若存在独立表）。
- **线程采样 (ThreadSample)**：线程维度在各采样点的占用（若存在独立表）。
- **洞察项 (Finding)**：类型（掉帧/稳定性/温度/功耗/频点/线程等）、严重程度、时间定位、支撑指标摘要、关联的**建议条目 (Recommendation)**。
- **对比会话对 (SessionComparePair)**：会话 A、会话 B 的摘要引用、可对齐指标列表、差异说明、警告标志（应用不一致等）。
- **解析任务 (ImportJob)**：源引用、状态（进行中/成功/失败）、用户可见消息、可取消性（若适用）。

## 非功能与体验要求 *(mandatory)*

- **NF-001 响应预期**：标准体量文件下，从确认导入到首屏摘要可用，目标与 **SC-001** 一致；超长帧表可采用**流式/分块**策略，但界面须保持可操作（非整窗冻结超过 **2 秒**无反馈）。
- **NF-002 资源占用**：在实现计划中约定**建议最大文件行数/内存上限**；超出时优雅降级（提示用户缩短导出时段），而非未捕获 OOM。
- **NF-003 无障碍与操作**：除拖拽外，MUST 提供**文件选择对话框**等价入口（键盘/鼠标均可完成一次完整分析流程）。
- **NF-004 日志与排障（内部）**：开发构建 SHOULD 记录解析失败原因摘要（不含完整用户路径）；正式发行版可关闭详细日志或仅写本地日志文件，**不默认回传云端**。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在常规办公设备上，**10 分钟内**可完成从拖入标准体量 PerfDog Excel（约百万行以下帧表或等效）到摘要报告首次展示，且用户无需查阅外部文档即可完成一次导入。
- **SC-002**: 对结构完整的样例文件，报告中的**会话元数据字段正确率 100%**（与文件内明示信息人工对照）。
- **SC-003**: 对含已知尖刺的样例，**至少 90%** 的尖刺时段被标记在「问题与洞察」中（允许时间窗口对齐误差在 ±2 个采样周期内）。
- **SC-004**: **95%** 的试用用户能在**首次使用 5 分钟内**找到：掉帧相关说明、温度相关说明、以及至少三条可执行建议（可用内部可用性自测或走查表验证）。
- **SC-005**: 错误文件场景下 **100%** 出现明确错误提示且无未处理崩溃（抽样至少 5 类异常输入）。
- **SC-006**: **90%** 的试用用户能在**首次使用 3 分钟内**完成「导出报告」或「复制报告」并在外部工具中验证内容完整。
- **SC-007**: 对两份结构完整的同应用样例，对比页展示的**可对齐指标**与人工逐列核对一致率 **100%**；应用不一致时 **100%** 出现需确认警告。
- **SC-008**: 对故意超过实现约定上限的文件（或在低端机上标准大文件），**100%** 出现可理解的「过大/资源不足」提示或分阶段加载说明，且**无未处理崩溃**。
- **SC-009**: 含 `@FrameInfo` 的样例中，报告须出现**至少一项**基于帧时长的量化结论（如「>16.67ms 帧占比」或「最大帧时刻」），且与 `@FrameInfo` 人工核对一致。

## Assumptions

1. 默认处理在**用户本机**完成，不上传原始 PerfDog 文件（除非产品后续明确扩展云功能）。
2. 首期以 **PerfDog Excel 导出** 为主流格式；CSV 或其他格式可作为后续增量。
3. 导出至少包含类似 **`all`（含汇总与 Data_v4）** 的工作表结构；`**@FrameInfo**`、`**@ThreadCpuUsageData**` 为增强能力，缺失时降级展示。
4. 「建议方案」为**规则与模板驱动的启发式输出**，不替代专业系统级性能追踪结论。
5. 目标用户为**游戏性能测试与调优人员**，具备基础 PerfDog 使用经验。
6. **Toolkit 集成**：默认指 **lv-game-toolkit** 桌面应用内新增入口；若未来拆分为独立应用，本 spec 中 FR-013 仍适用「同等入口能力」。
7. **界面语言**：默认中文；英文列为 PerfDog 导出原生列名时，报告中可中英并列或保留英文列名并附中文释义（实现计划定稿）。
8. **图表**：首期不强制内嵌折线图/热力图；若后续增加，须与本文本报告章节一致且不替代 FR-010 文本导出。

## Scope Boundaries

### In Scope

- Excel 导入、解析、摘要与问题洞察、频点/线程（若存在）关联摘要、建议清单、基础错误处理。
- 报告 **导出与复制**（FR-010，MUST）。
- **双会话对比**（FR-011/012，SHOULD/MUST 组合见上文）。
- **Toolkit 离线分析入口**（FR-013）。
- **游戏性能策略与 PerfDog 联合分析**（**JA-FR-001～008**，见下文 **US9～US11**）：在已加载 `gameperfconfig` 与已导入 PerfDog 报告的前提下，生成联合结论与绑核/频点类启发式建议，**不**自动改机或静默推送。

### Out of Scope

- 实时连接设备替代 PerfDog 采集。
- 自动修改游戏或系统设置。
- 保证与 Systrace/内核跟踪完全一致的根因定位。
- **三份及以上**会话的矩阵对比、统计检验（可作为更后续特性）。
- **自动调参 / 静默改机**：根据报告或联合分析 **自动** 修改 `gameperfconfig.xml`、**静默推送** 到设备或系统调度参数（不包含；联合分析仅输出建议，**JA-FR-008**）。
- **PerfDog 实时联机**：替代或嵌入 PerfDog 客户端实时采集（不包含）。

## Dependencies

- 用户提供合法获得的 PerfDog 导出文件。
- **lv-game-toolkit** 提供可挂载的 UI 入口与拖拽/文件对话框能力；实现计划需约定与现有 Tab 的导航与资源占用策略。
- 本规范不绑定具体编程语言与第三方库名称；技术选型在 `/speckit.plan` 中落地。
- **PerfDog 版本**：实现阶段须维护**已验证导出格式列表**（至少覆盖当前团队常用 1～2 个 PerfDog 版本）；版本升级导致列缺失时，降级策略见 Edge Cases。
- **游戏性能配置**：联合分析依赖 **`modules/game_perf`** 对 `gameperfconfig.xml` 的解析与 UI 选中游戏/模式；实现细节见 [plan.md](./plan.md) 联合分析小节与 [plan.md#数据模型](./plan.md#数据模型) 联合实体。

## 子特性：游戏性能策略与 PerfDog 联合分析

> **追溯**：原 `specs/005-gameperf-perfdog-analysis/` 已合并至本 spec。**权威文档目录**：**`specs/004-perfdog-import-insights/`**（与 [003-adb-enhancement](../003-adb-enhancement/) 同型：**仅** `spec.md`、`plan.md`、`tasks.md`；数据模型/调研/契约/实现记录均在 [plan.md](./plan.md)）。任务见 [tasks.md](./tasks.md) **Phase 12～16**（**US9～US11**）。

### User Story 9 - 联合视图与一致性结论 (Priority: P1)

性能测试人员在 Toolkit 中已打开 **游戏性能配置**（解析后的 `gameperfconfig.xml`）并选定 **游戏与模式**，同时已有一份 **PerfDog 会话**（或刚完成导入）。用户希望工具将 **当前策略中的频点表、绑核/亲和等相关设置** 与 **PerfDog 中观测到的 CPU 频点、占用、GPU、温度与帧率** 放在同一分析上下文中，生成 **可读结论**：策略是否与观测数据「方向一致」或存在明显矛盾（例如：策略鼓励大核高占但观测显示小核高频、或频点表上限与观测峰值长期脱节）。

**Why this priority**: 无联合结论则用户仍需人工对照两份数据，易遗漏矛盾，价值无法闭环。

**Independent Test**: 在固定样本（脱敏配置 + 脱敏 PerfDog）下，仅启用本能力即可得到至少一段「策略 vs 观测」的文字结论，无需改设备上的 XML。

**Acceptance Scenarios**:

1. **Given** 用户已在性能配置中选定游戏/模式且 XML 解析成功，**When** 用户选择或关联一份已导入的 PerfDog 报告并触发联合分析，**Then** 界面展示 **联合结论**（含策略摘要要点与观测摘要要点）。
2. **Given** PerfDog 与当前选中游戏 **包名或标识不一致**（若可判定），**When** 用户仍请求联合分析，**Then** 工具 **明确提示** 对比可能无意义，并允许用户选择继续或取消。

---

### User Story 10 - 绑核与频点的修改建议 (Priority: P2)

在联合分析基础上，用户需要 **针对绑核（或线程亲和相关策略项）与频点表（各温度/模式档下的频率上下限与索引）** 获得 **分条、可追溯的修改建议**：每条建议应说明 **依据哪类观测现象**（如最低帧邻域 CPU 核占用、频点分布、温度平台期等），并采用 **「建议复测验证」** 式措辞，**不得**断言未经数据支持的确定根因。

**Why this priority**: 须在 US9 有数据对齐后才可信。

**Independent Test**: 使用含明显「单核打满 / 多核闲置」或「长期触顶频点」特征的合成或脱敏数据，建议列表中至少出现一条与 **绑核** 或 **频点表** 明确相关的条目，并带追溯说明。

**Acceptance Scenarios**:

1. **Given** 联合分析已生成结论，**When** 用户查看「策略调整建议」区域，**Then** 可见 **绑核类** 与 **频点类** 建议（若数据不足以支持某一类，则 **明确标注「当前数据不足以给出该类建议」**）。
2. **Given** 用户导出联合报告，**When** 打开导出文本，**Then** 结论与建议章节与界面一致，且建议仍含 **推断性质** 说明。

---

### User Story 11 - 与现有工作流衔接 (Priority: P3)

用户可在 **不推送设备** 的情况下完成联合分析；若用户随后在性能配置中 **手动** 按建议修改 XML，应能 **再次运行联合分析** 对比前后差异（至少通过重新加载配置与保留上一份 PerfDog 报告实现）。

**Why this priority**: 降低试错成本，形成迭代闭环。

**Independent Test**: 修改本地 XML 后重新解析，联合分析能反映更新后的策略摘要。

**Acceptance Scenarios**:

1. **Given** 用户未连接设备，**When** 仅使用本地 XML 与已导入 PerfDog，**Then** 仍可完成联合分析与建议展示。

### 联合分析 — Edge Cases

- `gameperfconfig.xml` 未加载、解析失败或与所选游戏/模式不匹配：应阻断联合分析并提示先修复性能配置侧问题。
- PerfDog 缺少 CPU 频点/占用等关键列：应降级输出结论（仅基于可用列），并列出 **缺失数据对建议范围的影响**。
- 多模式、多温度档：联合分析默认对齐 **当前 UI 选中的模式**（及与之对应的策略块）；跨模式对比可作为后续增强。
- 包名/应用不一致：须提示，避免将 A 游戏策略与 B 应用 PerfDog 强行对齐。
- 建议涉及越安全边界的系统行为（如极端调频）：措辞须保守；**不自动改机**（见 **JA Out of Scope**）。

### 联合分析 — Functional Requirements (JA-FR)

- **JA-FR-001**: 工具 MUST 能读取 **当前在性能配置中生效的**（或用户显式指定的）`gameperfconfig` 解析结果中与 **频点表、绑核/亲和相关策略** 有关的结构化摘要，用于联合分析展示。
- **JA-FR-002**: 工具 MUST 能读取 **已导入的 PerfDog 分析结果**（会话级指标、最低帧/掉帧相关洞察及可用的 CPU/GPU/温度/频点列统计），作为联合分析的观测侧输入。
- **JA-FR-003**: 工具 MUST 生成 **联合结论**，至少包含：**策略侧要点**、**观测侧要点**、**一致性/矛盾点** 三段语义（可用条目列表呈现）。
- **JA-FR-004**: 工具 MUST 生成 **绑核/亲和相关** 与 **频点表相关** 的 **修改建议**；在数据不足时 MUST **显式说明** 无法给出该类建议的原因。
- **JA-FR-005**: 所有建议 MUST 标注 **启发式/需复测验证**，且 MUST 能关联到 **具体观测依据**（用户可理解的描述，而非内部字段名堆砌）。
- **JA-FR-006**: 当 PerfDog 会话与配置游戏 **应用标识不一致**（在可解析且可比对的前提下），工具 MUST **警告** 并遵循用户选择是否继续。
- **JA-FR-007**: 用户 MUST 能将联合结论与建议 **导出** 为可分享文本（与现有 PerfDog 报告导出能力 **合并或分节** 均可，但须 **一次可读**）。
- **JA-FR-008**: 工具 MUST NOT **未经用户确认** 直接修改设备上的 `gameperfconfig.xml` 或执行推送；策略变更仍为 **用户手动** 在性能配置中完成。

### 联合分析 — Key Entities

- **PolicySnapshot**：当前 `gameperfconfig` 与联合分析相关的子集（频点档位、绑核语义化摘要等）。详见 [plan.md#数据模型](./plan.md#数据模型)。
- **ObservationsSnapshot**：由 `AnalysisReport` 派生的观测视图。
- **JointAssessmentReport**：结论 + 分类建议 + 数据不足说明 + 警告。

### 联合分析 — Success Criteria (JA-SC)

- **JA-SC-001**: 在标准脱敏夹具（配置 + PerfDog）上，测试人员可在 **5 分钟内** 完成从「选定游戏/模式 + 关联 PerfDog」到「阅读完整联合结论」的路径。
- **JA-SC-002**: **90%** 以上的试用用户能在 **首次阅读** 时正确说出联合结论中 **至少一条** 「策略 vs 观测」关系（走查表验证）。
- **JA-SC-003**: 对于夹具中故意设计的 **绑核或频点与观测明显不一致** 场景，报告 MUST 在 **建议或矛盾点** 中 **至少命中一类** 可理解的提示。
- **JA-SC-004**: 在 PerfDog **缺失 CPU 频点列** 的夹具上，报告 MUST **不出现** 伪造的频点对比结论，且 MUST 包含 **缺失数据说明**。

### 联合分析 — Assumptions

- 用户在同一 Toolkit 会话内使用 **游戏性能配置** 与 **PerfDog 分析**；「当前策略」默认取性能配置中 **已解析且选中的游戏/模式**。
- 「绑核」对应 `gameperfconfig` 中与 **线程/CPU 亲和或绑定** 相关的字段；字段映射在 [plan.md](./plan.md) 对齐工程现状。
- PerfDog 数据为 **秒级/采样级**；与 **单帧级** 结论的层级须在结论中明确。

### 联合分析 — Out of Scope

- 自动将建议写回 XML 并 **静默推送** 到设备。
- 替代 PerfDog 采集或替代系统级跟踪工具做 **唯一根因裁定**。
- 跨项目通用的「最优频点」自动搜索算法（遗传算法、全局自动调参等）。
- 法务/合规未授权场景下的数据上传与云端对比。
