## 1. 设计的本质：商用感从哪来

### 1.1 "土"和"专业"差在哪

同一套功能，业余界面和专业界面的差别**不在功能**，而在五个可量化的维度：

| 维度 | 业余界面 | 专业界面 |
|------|---------|---------|
| **一致性** | 每个控件随手设计，密度/字号/圆角各不相同 | 一套 token 贯穿全应用，处处统一 |
| **层次** | 所有元素同样醒目，看不出主次 | 主次分明，一眼找到主操作 |
| **状态完备** | 只有默认态，hover/focus/disabled 缺失 | 每种交互状态都有反馈 |
| **细节打磨** | 图标发虚、圆角乱、间距失衡 | 图标清晰、间距规整、动效克制 |
| **流畅度** | 操作假死、卡顿、无进度反馈 | 不阻塞、有进度、响应快 |

**结论**：商用感 ≈ 一致性 × 层次 × 状态 × 细节 × 流畅。五个都是"系统工程"，不是某个按钮画好看点。

### 1.2 三个根本原则

1. **一致性（Consistency）**：同类控件永远长一样、动一样、放一样的位置。这是专业感的基石。
2. **清晰的层次（Hierarchy）**：每个界面只有一个主角（主操作），其余按重要度递减排列。
3. **状态完备（States）**：任何可交互元素，在鼠标/键盘/触摸的每一种状态下都有正确反馈。

## 2. 设计 Token 体系：先定规矩，再画界面

### 2.1 什么是 Design Token

Design Token = 把设计里的**所有取值**抽成命名变量，全应用唯一来源（Single Source of Truth）。

```
不这样：每个页面分别写 "padding: 6px 16px" / "color: #cba6f7"
要这样：统一从 token 取值
        space-md = 16px     color-accent = #cba6f7
```

**价值**：改一处，全应用生效；密度/配色天然统一；主题切换只换 token。

### 2.2 五类核心 Token

| 类别 | 典型 token | 说明 |
|------|-----------|------|
| 颜色 | `color-bg` / `color-fg` / `color-accent` / `color-success` / `color-error` | 背景分层、前景分层、强调、语义 |
| 间距 | `space-xs`(4) / `space-sm`(8) / `space-md`(16) / `space-lg`(24) | 基于 8pt 网格 |
| 字号 | `font-sm`(12) / `font-md`(14) / `font-lg`(18) / `font-xl`(24) | 建立 4-5 级字阶 |
| 圆角 | `radius-sm`(2) / `radius-md`(4) / `radius-lg`(8) / `radius-full`(圆) | 2-4 档足够 |
| 阴影 | `shadow-sm` / `shadow-lg` | 浮层/对话框/卡片层级 |

### 2.3 8pt 网格（间距体系的核心）

- 所有间距、尺寸、行高用 **8 的倍数**（4/8/16/24/32…）。
- 小到控件 padding、大到区块间距，全部落在这个网格上。
- 图标尺寸 16/24/32，控件高度 32/40/48 —— 都在网格上，界面天然整齐。

**为什么是 8**：主流屏幕尺寸多为 8 的倍数，能整除大多数布局；比 10pt 网格更紧凑、更专业。

## 3. 布局与信息架构：东西放哪

### 3.1 信息架构流程（先想清楚再画）

1. **内容清单**：列出界面所有内容，按「操作 / 配置 / 数据 / 状态」分类。
2. **分主次**：主任务流上的内容放前面、放显眼处；低频内容折叠或收进二级。
3. **定导航**：能放进一层就不加一层，层级越深用户负担越重。

### 3.2 布局范式

不同平台/场景的通用布局骨架：

| 场景 | 布局骨架 | 说明 |
|------|---------|------|
| 桌面工具/IDE | 侧边导航 + 主内容区 + 底部面板（VSCode 式） | 信息多、需并排看 |
| Web 管理后台 | 左侧菜单 + 顶栏 + 内容区 + 右侧详情 | 中后台通用 |
| 移动端 | 底部 Tab + 内容流 + 顶部导航 | 单手可达 |

**通用规则**：
- 主内容区永远是最大块。
- 工具栏/操作行高度克制，不喧宾夺主。
- 留白是设计的组成部分，不是浪费。

### 3.3 一个界面一个主操作

- 每个界面只允许**一个**最突出的操作（primary 按钮）。
- 其余操作全部降级为 secondary / ghost / 菜单项。
- 判断法：如果用户问"我应该点哪个"，说明主操作不够突出。

## 4. 视觉层级：让眼睛知道看哪

### 4.1 用色层次

- **一个主色**（accent）：只用于选中、主操作、链接。全应用只有这一个"主角色"。
- **语义色**（成功/错误/警告/信息）只表达状态，不参与装饰。
- 背景分层：应用背景 → 面板 → 控件 → 边框 → 前景，逐层递进，层次清晰。
- **不要彩虹**：一个界面出现 3 种以上高饱和色，立刻显得业余。

### 4.2 字体层级

- 建立 4-5 级字阶：辅助(11-12) / 正文(13-14) / 强调(16) / 标题(20) / 大标题(28+)。
- 同屏最多 2-3 种字重对比（regular / medium / bold），不滥用加粗。
- 全局定义字体，模块/页面不重复设置。

### 4.3 对比度与可读性（可量化）

文本与背景的对比度是**数学标准**（[WCAG 2.1](https://www.w3.org/TR/WCAG21/#contrast-minimum)）：

| 目标 | 要求 |
|------|------|
| 普通文本（AA，法规基线） | ≥ **4.5:1** |
| 大文本（≥24px 或 18.66px 加粗） | ≥ **3:1** |
| 图形 / 图标 / 输入框边框 | ≥ **3:1**（WCAG 2.1 新增） |
| 普通文本（AAA，增强） | ≥ **7:1** |

**实践**：正文用 4.5:1 以上；禁用/次要文字可以降低（如 3:1 附近）但不要太低到看不清。设计时用对比度检查工具实时验证，不靠肉眼。

### 4.4 圆角、边框、阴影

- 圆角 2-4 档即可（小控件 2-4，面板 8，弹层 12+），全应用统一。
- 边框一律细（1px），用 border 色不用纯黑。
- 阴影用于表达**层级**：普通内容无阴影，浮层/对话框/菜单有阴影，层级越高阴影越重。

## 5. 交互状态完备：把状态做全

### 5.1 六态模型

**任何可交互控件**都必须定义 6 种状态（商用感和业余界面的最大分水岭）：

```
normal（默认）
  → hover（悬停：背景/边框提亮）
  → pressed（按下：压暗）
  → focus（键盘聚焦：统一 focus ring）
  → disabled（禁用：降灰 + 可提示原因）
  → active（选中/激活：accent 强调）
```

**常见缺失**：
- **focus** 最常被忽略 —— 设了 `outline: none` 却不补 focus 样式（键盘用户直接失去导航能力）。
- 选中态不分窗口**活动/失活**两级（列表在窗口失活时仍高亮会误导）。
- disabled 只改透明度不降饱和，容易和 hover 混淆。

### 5.2 focus ring（键盘焦点环）

- 所有可交互元素 Tab 可达，聚焦时必须有清晰指示。
- 统一 focus ring：1-2px 强调色边框 + 轻微外发光/偏移。
- **禁止**关闭 outline 后不补任何 focus 样式。

### 5.3 空 / 错 / 加载三态

| 状态 | 要求 |
|------|------|
| **空状态** | 图标 + 一句"为什么空 + 下一步怎么做"，不留白板 |
| **错误状态** | 可读的错误信息 + 可操作建议（重试/检查），不裸抛技术栈 |
| **加载状态** | 进度指示 + 阶段性文案，耗时操作禁用重复点击 |
| **禁用状态** | 降灰 + hover tooltip 说明原因 |

## 6. 分辨率与多屏适配

### 6.1 核心概念：逻辑像素 vs 物理像素

- **逻辑像素（DIP/CSS px）**：设计时用的单位。
- **物理像素**：屏幕真实像素，高 DPI 屏物理像素是逻辑像素的 2-3 倍（DPR=2/3）。
- 界面按**逻辑像素**设计，系统负责映射到物理像素。

### 6.2 DPI 缩放与"发虚"（桌面端核心坑）

Windows 的 DPI Awareness 决定应用如何应对缩放，**选错模式 = 界面发虚**（来源：[Microsoft Learn — High DPI](https://learn.microsoft.com/en-us/windows/win32/api/_hidpi/)）：

| 模式 | 行为 | 后果 |
|------|------|------|
| **DPI Unaware**（默认，未声明） | 应用假设 100% 缩放，由系统 bitmap 拉伸 | **整屏发虚**，坚决避免 |
| System DPI Aware | 启动时读一次 DPI，跨屏不更新 | 拖到不同 DPI 屏幕会糊 |
| Per-Monitor V1 | 检测 DPI 变化并重缩放 | 可用，但非客户区/对话框缩放不完整 |
| **Per-Monitor V2**（推荐） | 完整的多屏 DPI 感知，子控件/对话框自动缩放 | 现代桌面应用首选 |

**实操要点**：
- 桌面应用声明 Per-Monitor V2（manifest 或 API），**不要用 DPI Unaware**。
- Web 天然适配（浏览器负责），但要注意 `meta viewport` 和 rem/em 单位。
- 测试：在 100% / 125% / 150% / 200% 缩放 + 多显示器混合 DPI 下分别截图验证。

### 6.3 多分辨率适配策略

| 策略 | 适用 | 做法 |
|------|------|------|
| **弹性布局**（推荐） | 桌面/中后台 | 控件大小固定，容器弹性伸缩，窗口可缩放 |
| **响应式** | Web/移动 | 断点切换布局（如 <768px 单列） |
| **固定布局** | 专用小工具 | 锁定最小窗口尺寸，内容居中或滚动 |

**通用原则**：
- 优先**弹性布局**，控件尺寸固定（token 控制）、容器填满可用空间。
- 定义**最小窗口尺寸**，过小则启用滚动，避免控件被裁切。
- 高分屏上文字/控件不应变大，而是**更清晰**（更多物理像素）；放大应通过"界面缩放设置"而非 DPI 模糊。

### 6.4 多倍图资源

| 类型 | 做法 |
|------|------|
| 矢量图（SVG / 图标字体） | **首选**，任意 DPI 都清晰 |
| 位图（PNG/JPG） | 提供 1x/2x/3x 多倍图，按 DPR 加载 |
| 自定义绘制 | 画布用物理像素分辨率，逻辑尺寸适配 |

## 7. 渲染质量：发虚 / 模糊 / 锯齿从哪来

### 7.1 字体渲染

Windows 上两个渲染引擎的权衡（来源：[MacType — DirectWrite vs GDI](https://github.com/snowie2000/mactype/wiki/DirectWrite-vs-GDI)）：

| 引擎 | 特点 | 最佳场景 |
|------|------|---------|
| **GDI / ClearType** | 像素对齐、锐利；仅水平子像素抗锯齿，大字号对角线锯齿 | 小字号（9-16px）正文 |
| **DirectWrite** | 亚像素定位、垂直+水平抗锯齿、更平滑；OpenType 支持好 | 大字号、标题、现代 UI |

**实操**：
- 现代应用默认走 DirectWrite 系（更平滑、跨 DPI 一致），UI 正文 14px+ 观感好。
- 等宽字体/代码用带 ClearType 的渲染模式更锐利。
- 避免在小字号用细字体 + 低对比度（叠加发虚）。

### 7.2 图标清晰度

| 方案 | 清晰度 | 推荐度 |
|------|--------|--------|
| **SVG / 图标字体** | 任意 DPI 清晰 | ✅ 首选 |
| 位图多倍图（1x/2x/3x） | 匹配 DPR 时清晰 | ⚠️ 次选 |
| 单尺寸位图 | 非原尺寸缩放发虚 | ❌ 避免 |

- 图标设计在 24x24 网格上，导出 SVG。
- 避免对小图标做缩放模糊；用字体渲染图标时确保字体文件清晰。

### 7.3 抗锯齿与缩放模糊

- 图形绘制开启抗锯齿（AA），线条落在 0.5px 网格避免 1px 线变 2px 粗线。
- 非整数缩放（如 125%）下，位图和 1px 边框都会"模糊/深浅不一"，属系统限制，尽量：逻辑布局 + 矢量绘制 + 动态 1px（`1/dpr`）。

## 8. 动效：加分项，宁缺毋滥

### 8.1 动效原则

1. **有目的**：表达状态变化、方向引导、层级关系，不为炫技。
2. **克制**：只做关键路径（面板展开、内容过渡、加载反馈），不做满屏动画。
3. **一致**：全应用同一种时长/缓动曲线，观感统一。

### 8.2 时长与缓动参考

- 短反馈：**100-200ms**（按钮、hover、小过渡）。
- 结构变化：**200-300ms**（面板展开收起、内容切换）。
- 大过渡：**300-500ms**（页面切换）。
- 缓动：进入用 ease-out（快进慢停），退出用 ease-in，避免线性（机械感）。

### 8.3 平台限制（先认清再设计）

- Web：CSS transition / animation 成熟。
- 部分原生框架（如 Qt QSS）**不支持** transition，需用动画 API 对几何/透明度插值 —— 设计时评估平台能力，别设计实现不了的动画。

## 9. 性能与流畅度：UI 不阻塞是一切的前提

界面再好看，一操作就假死 = 零分。性能是 UX 的一部分。

### 9.1 UI 线程不阻塞（多进程/多线程架构的借鉴）

大型商业应用（如 VSCode）用多进程保证 **UI 线程永不阻塞**。单进程应用可用多线程达到同等效果：

| 借鉴点 | 做法 |
|--------|------|
| **UI 线程只做界面** | 布局、绘制、事件分发在 UI 线程；所有重活（IO、计算、网络）进 worker 线程/进程 |
| **异步反馈** | 耗时操作立即给进度反馈，完成后回主线程更新 |
| **渐进式启动** | 先显示窗口壳，再异步加载模块/插件，最后后台初始化 —— "秒开"体感 |
| **崩溃隔离** | 极端重活（渲染、插件）隔离到独立进程，崩溃不影响主 UI |

### 9.2 大数据量：虚拟滚动

- 渲染几百上千行时，**只渲染可见区域**（virtual scrolling / windowing），不要全量创建控件。
- 判断信号：数据量 > 200-500 条时，就该考虑虚拟化。
- 表格单元格塞复杂控件（下拉/按钮）尤其要警惕 —— 每行都是对象，量大了必卡。

### 9.3 渐进增强与性能预算

- 首屏优先：首屏只加载必要内容，非关键模块懒加载。
- 图片/图标懒加载。
- 为关键路径设性能预算（如"抓取操作 1 秒内反馈"），超标即优化。

## 10. 无障碍与键盘可达

无障碍不是加分项，是**工程要求**（很多国家有法规约束，WCAG AA 是通行基线）。

| 维度 | 要求 |
|------|------|
| **对比度** | 文本 ≥4.5:1（AA）、UI 组件 ≥3:1 |
| **键盘导航** | 全功能 Tab 可达，focus ring 清晰 |
| **焦点顺序** | 遵循视觉阅读顺序（左→右，上→下） |
| **目标尺寸** | 可点目标 ≥ 44×44 CSS px（移动端）或 ≥24px 核心目标 |
| **语义** | 图标按钮有可读的文本/aria-label，不只靠颜色传达状态 |
| **触控** | 触摸区域不小于手指接触面，常用操作单手可达 |

## 11. 多主题 / 暗色模式

- 用 token 体系实现主题，暗色/亮色只换 token，不重写界面。
- 暗色模式不是"反色"：用降低明度的深灰/黑蓝（非纯黑），前景/背景逐层降亮。
- 主题切换时**所有元素**（含图表、自定义绘制、日志高亮）跟随，禁残留单主题硬编码。
- 提供跟随系统主题的选项。

### 12.1 截图对比法

1. 改前全界面截图（多主题、多缩放）存 `before/`。
2. 改后存 `after/`，逐项对照：间距统一吗？状态全吗？清晰吗？

### 12.2 多环境验证清单

- [ ] 多分辨率（最小尺寸 / 大屏）
- [ ] 多 DPI 缩放（100/125/150/200%）
- [ ] 多主题（暗色/亮色）
- [ ] 键盘全流程走查（不用鼠标完成一个任务）
- [ ] 大数据量压力（千行列表是否卡）
- [ ] 慢速环境（加载反馈是否正常）

### 12.3 可用性快检（5 人法则）

找 3-5 人各花 5 分钟走主任务流，记录：卡在哪一步、有无误操作、最不喜欢的部分。低成本、高收益。

## 14. 常见误区

| 误区 | 真相 |
|------|------|
| "先画好看再统一" | 一致性是地基，后补的代价是全部重做 |
| "颜色越丰富越好看" | 主色单一 + 语义克制才是专业 |
| "加了动画显得高级" | 滥用的动画显廉价，关键路径克制动画才对 |
| "高分屏会自动清晰" | 不声明 DPI 感知 = 系统拉伸 = 发虚 |
| "无障碍是额外工作" | 对比度/焦点/语义是工程基线，很多地区是法规 |
| "性能是后端的事" | UI 假死直接毁掉所有设计，前端渲染同样关键 |
