## 1. 设计前置：动手前先想清楚

**不要一上来就画界面。** UI 设计的第一件事是搞清楚"给谁用、干什么、怎么干"。

### 1.1 回答五个问题（动手前的必答题）

| 问题 | 说明 | 本项目的典型答案 |
|------|------|------------------|
| **谁用？** | 使用者角色、熟练度 | 游戏性能测试工程师 / 开发；熟悉 ADB 但不想记命令行 |
| **干什么？** | 核心任务，不是功能列表 | 连设备 → 抓 trace → 分析 jank → 改性能配置 → 出报告 |
| **在哪用？** | 平台、屏幕、输入方式 | Windows 桌面，鼠标为主，键盘为辅 |
| **什么时候用？** | 使用场景的紧迫度 | 性能排查时，追求"少点几次、快出结果" |
| **为什么需要界面？** | 相比命令行的增量价值 | 可视化配置、历史回溯、Agent 对话、参数不靠记 |

**产出**：一段话的产品定位。例如 perfetto_capture 的定位 = "让性能工程师 3 步内完成 trace 抓取"。

### 1.2 梳理核心任务流

每个模块画一条**主任务流**（用户在 90% 情况下走的路径）：

```
perfetto_capture 主任务流：
连接设备 → 选抓取配置 → 点「开始抓取」→ 等待/看进度 → 停止 → 看报告 → 可选：发送给 Agent 分析
```

画出来后：
- **主流程上的每一步** = 界面必须一眼能找到的东西。
- **不在主流程上的** = 折叠、放二级菜单、不占主视觉。

### 1.3 盘点现状（改造已有界面时）

改造前先回答：

- 这个界面现在有哪些元素？按「操作 / 配置 / 数据 / 状态」分类列出来。
- 哪些元素用户**经常用**、哪些**几乎不用**？（访谈或日志统计）
- 当前最大的痛点是什么？（挤、乱、卡、找不到按钮）

### 1.4 收集参考（Reference）

- **布局参考**：VSCode（本项目的对标目标）、PerfDog、Android Studio Profiler、Chrome DevTools。
- **做法**：截图存到 `private/references/`，标注"好在哪里 / 我要借鉴什么"。
- **不要照抄**：参考的是**设计决策**（为什么这样排），不是像素。

## 2. 信息架构（IA）：把内容组织清楚

信息架构决定"东西放在哪"，是布局的前提。这一步错了，后面画得再好看也乱。

### 2.1 内容清单法

把界面需要的**所有内容**先写成清单，不打散：

| 内容 | 类型（操作/配置/数据/状态） | 频率（高/中/低） | 主流程？ |
|------|---------------------------|-----------------|---------|
| 设备选择 | 操作 | 高 | ✅ |
| 抓取时长 | 配置 | 中 | ✅ |
| 开始/停止按钮 | 操作 | 高 | ✅ |
| 抓取进度 | 状态 | 高 | ✅ |
| atrace 类别勾选 | 配置 | 低 | ❌（高级） |
| 历史会话树 | 数据 | 中 | ❌ |

### 2.2 分组与层级

规则：
1. **按任务分组**，不按控件类型分组（"抓取相关"放一起，不是"所有按钮放一起"）。
2. **一个界面一个主操作**（最显眼那个），其余是次操作。
3. **高频前置，低频收纳**：常用的不折叠，高级/低频的折叠进「高级」或 Tab。

### 2.3 导航范式选择

本项目有三层导航，明确每层职责：

| 层级 | 职责 | 例子 |
|------|------|------|
| 顶部 Tab 栏 | 一级大域 | Agent / 工具集 |
| 左侧导航 | 模块切换 | 伪装 / 性能 / 日志 / Trace |
| 模块内 Tab | 模块内部的视图切分 | 编辑 / 对比 |

**原则**：能塞进一层就不多加一层；层级加深 = 用户记忆负担加重。

### 2.4 命名一致性

- 动词开头表动作（「开始抓取」「导出报告」）。
- 同一概念全文一个词（不要一会儿"配置"一会儿"设置"）。
- 涉及用户可见中文文本，一律走模块 `strings_gui.py` 常量（见 [string-extraction-gate](../.claude/rules/string-extraction-gate.md)）。

## 3. 布局设计：搭骨架

IA 决定"有什么"，布局决定"长什么样、排哪"。

### 3.1 本项目骨架（已有，理解即可）

```
┌──────────┬─────────────────────────────┐
│ NavPanel  │ ContentStack                │
│ (180px)   ├────────────────────────────┤
│          │ BottomPanel（日志，可折叠）    │
├──────────┴────────────────────────────┤
│ StatusBar                               │
└───────────────────────────────────────┘
（RightPanel 为 overlay 浮层，可开关）
```

对应代码：[main_window.py](../toolkit/gui/main_window.py) 中 `_splitter`（左右）+ `_center_splitter`（上下）+ `_body_container`（右侧 overlay）。

### 3.2 标准模块布局模板

每个模块 Tab 建议按以下**四段式**组织（参照 VSCode 内容区范式）：

```
┌──────────────────────────────────────────┐
│ ① 工具条（可选，高 36px）                  │  ← 高频动作、模块级筛选
├──────────────────────────────────────────┤
│ ② 配置区（GroupBox 卡片）                 │  ← 主流程参数，一眼可见
│    ┌─────────┐ ┌─────────┐              │
│    │ 配置组A   │ │ 配置组B   │              │
│    └─────────┘ └─────────┘              │
├──────────────────────────────────────────┤
│ ③ 主内容区（表/树/图，占大部分空间）       │  ← 数据展示主体
│                                          │
├──────────────────────────────────────────┤
│ ④ 操作行（主操作靠右）                     │  ← 开始/导出/保存
└──────────────────────────────────────────┘
```

**布局优先级**：③ 主内容区永远是最大块；① 和 ④ 高度克制。

### 3.3 间距与密度（8px 基准）

- 所有间距用 8px 基准体系（[DES-003 §3.2](../docs/design/DES-003-ui-design-standards.md#32-间距与密度-token)）：4/8/12/16/24。
- 控件最小高度 28px；列表行高 22px；导航项 32px。
- **禁止**随手写 `padding: 5px`、`margin: 3px` 打散密度。

### 3.4 画线框（Wireframe）的实操

- **快速版**：ASCII 线框（本文件里这种），几秒画一个，用来对齐布局。
- **精细版**：Qt Designer（`.ui` 文件）或直接写代码原型。
- **原则**：线框阶段**不纠结颜色**，只定布局、层级、留白。颜色是视觉阶段的事。

## 4. 视觉设计：让界面"好看"

"好看"在本项目 = **统一 + 层次 + 状态完备**。三者缺一，界面就"土"。

### 4.1 颜色体系（Catppuccin + 语义色）

- 背景/前景/强调/语义色已集中在 [theme_colors.py](../toolkit/gui/theme_colors.py)，**模块代码一律从这里取，禁止硬编码 hex**。
- 设计时的用色层次（从深到浅）：
  1. 应用背景 `bg`
  2. 面板/卡片 `panel_bg` / `card_bg`
  3. 控件背景 `input_bg` / `hover`
  4. 边框 `border` / `border_subtle`
  5. 前景 `fg` / `fg_dim` / `fg_muted`
  6. 强调 `accent`（用于选中、主操作）
  7. 语义 `success` / `error` / `warning` / `info`
- 需要补充的 token（focus_border / badge / shadow 等）见 [DES-003 §3.1](../docs/design/DES-003-ui-design-standards.md#31-颜色-token)。

**设计原则**：
- 一个界面的"主色"只有 1 个（accent），语义色只表达状态，**不要彩虹**。
- 背景层级越深越暗（暗色主题），越浅越亮（亮色主题）。

### 4.2 字体层级

| 场景 | 字体 | 大小 |
|------|------|------|
| 正文/控件 | Segoe UI / Microsoft YaHei UI | 12px |
| 强调标题 | 同上，粗体 | 13-14px |
| 状态栏/日志 | Segoe UI | 11px |
| 日志内容 | Cascadia Code / Consolas | 11px |

- 全局字体在 [styles.py](../toolkit/gui/styles.py) 的 `QWidget { font-family... }` 定义，模块不重复设。

### 4.3 圆角、边框、阴影

- 圆角四档：2（CheckBox）/ 4（输入框、按钮）/ 6（面板、卡片）/ 8（对话框、气泡）。
- 边框用 `border` / `border_subtle`，**1px**，不做粗边框。
- 阴影用 `QGraphicsDropShadowEffect`（对话框/弹出层），模块不自己实现。

### 4.4 组件规范（每种控件长什么样）

| 组件 | 规范要点 |
|------|---------|
| 主按钮 `#primaryBtn` | accent 底 + 深色字，一个界面只允许一个"主" |
| 次按钮 `#secondaryBtn` | 控件色底 + 边框 |
| 危险按钮 `#dangerBtn` | 透明底 + error 色边框，hover 才实底 |
| 图标按钮 `#ghostBtn` | 无背景无边框，hover 才出现圆角背景 |
| 输入框 | 控件底 + 边框，focus 时边框变 accent |
| 下拉 | 同输入框，弹出列表项 hover 高亮 |
| 表格/树 | 斑马纹 + 选中高亮，表头灰底粗体 |
| 卡片 `#moduleCard` | 边框 1px，hover 边框提亮 |

### 4.5 状态完备（六态）

**每个交互控件必须有 6 种状态反馈**，这是"商用感"的核心分水岭：

```
normal（默认） → hover（悬停提亮） → pressed（按下压暗）
→ focus（键盘聚焦，统一 focus_border 环） → disabled（降灰）
→ active（选中/激活，accent 强调）
```

对照检查：
- 按钮：hover/pressed/disabled/focus 都要有。
- 输入框：focus 换边框色；hover 轻微提亮。
- 列表/树：选中态分**窗口活动/失活**两级（`selection_bg` / `selection_bg_inactive`）。
- **禁**设 `outline: none` 却不补 focus 样式。

### 4.6 在 PyQt6 里怎么落地视觉

```
视觉定义集中在 3 个地方，模块代码只做"引用"：
├── theme_colors.py   → 颜色 token（get_colors(theme)）
├── styles.py         → 全局 QSS（控件长相、状态）
└── design_tokens.py  → 间距/字号/圆角（DES-003 Phase 1 新增）
模块内：
├── setObjectName("primaryBtn")   ← 挂到全局 QSS 规则
└── 绝不写 setStyleSheet(...) 覆盖主题（例外：运行时动态状态切换）
```

**禁止清单**（来自 [ui-style-guide](../.claude/rules/ui-style-guide.md)）：
- ❌ 模块内定义颜色字典 `_THEME_COLORS = {...}`
- ❌ 静态样式用 `setStyleSheet("font-size: 13px; ...")`
- ❌ 硬编码主题色值（`#1e1e2e`）
- ❌ 用 Unicode Emoji 当图标（用 codicon 字体）

## 5. 交互设计：让界面"好用"

视觉解决"好不好看"，交互解决"顺不顺手"。

### 5.1 反馈设计

每个操作必须有反馈，且**反馈要对得上操作的轻重**：

| 操作 | 反馈 | 说明 |
|------|------|------|
| 点击按钮 | 立即响应（hover/pressed 变色） | 无感即「假死」 |
| 耗时操作（抓取/分析/推送） | 进度条 / 进度日志 + 按钮禁用 | 必须让用户知道"在干活、别点第二次" |
| 成功 | success 色日志 + 可见结果 | 完成后告诉用户"然后呢"（如打开导出目录） |
| 失败 | error 色日志 + 可读的错误原因 | 不要裸抛 traceback 给用户 |
| 空数据 | 空状态占位（图标 + 一句话） | 别只留一片空白 |

### 5.2 数据展示密度

- 表格/树是"信息密度高的专业工具"，行高紧凑（22px）、列可排序、支持搜索。
- **大列表必须考虑虚拟化**：本项目 QTreeWidget/QTableWidget 全量加载，数据量大时会卡（[DES-003 §7.4](../docs/design/DES-003-ui-design-standards.md#74-p3-性能与虚拟滚动)）。
- 表格列过多时（>6 列）考虑分组/折叠/详情抽屉。

### 5.3 空状态、错误状态、加载状态

| 状态 | 设计要点 |
|------|---------|
| 空状态 | 图标（codicon）+ 一句"为什么空 + 下一步怎么做" |
| 错误状态 | error 色 + 可操作的建议（"设备未连接，点击重试"） |
| 加载状态 | 进度条/转圈 + 阶段性文案（不是一直"处理中"） |
| 禁用状态 | 灰 + 鼠标悬浮提示原因（tooltip） |

### 5.4 键盘与焦点

- 所有可交互元素 Tab 可达，聚焦时有清晰 focus 环。
- 高频操作配快捷键（Ctrl+S 保存、Ctrl+F 搜索）。
- 本项目推进方向：命令面板 Ctrl+Shift+P（[DES-003 §6.1](../docs/design/DES-003-ui-design-standards.md#61-命令面板ctrlshiftp)）。

## 6. 动效：加分项，别滥用

### 6.1 Qt 的能力边界（先认清）

- QSS **不支持** CSS transition/animation（这是硬限制，别花时间找语法）。
- 可用 `QPropertyAnimation` / `QGraphicsOpacityEffect` 对**几何/透明度**做插值。

### 6.2 值得做的关键动效

| 场景 | 动画 | 时长 |
|------|------|------|
| 面板展开/收起 | 高度/宽度插值 | 150ms |
| 右侧面板淡入 | 透明度 | 120ms |
| 模块 Tab 切换 | 透明度 | 100ms |

**原则**：只做**关键路径**，模块不要各自实现动画；过度动画反而显"廉价"。

## 7. 验证与迭代：好看不好看，靠对比说话

### 7.1 截图对比法（最有效）

1. 改前给界面截图（暗色/亮色各一张）存到 `private/screenshots/before/`。
2. 改后截图存到 `after/`。
3. 逐项对照，回答：间距统一了吗？状态反馈全吗？层次清楚吗？

### 7.2 VSCode 对标清单（逐项打勾）

## 10. 常见坑与避坑

| 坑 | 表现 | 避坑 |
|----|------|------|
| **硬编码颜色** | 换主题后某处颜色不跟随、发灰 | 一律 `get_colors()`；审查脚本抓硬编码 hex |
| **内联 setStyleSheet** | 样式与全局不一致、难维护 | 走全局 QSS + objectName；仅动态状态可内联 |
| **objectName 拼写错** | 按钮样式"消失"降级为默认 | 与 styles.py 规则逐字核对；新 objectName 先加 QSS |
| **padding 随手填** | 界面密度混乱、显"土" | 只用 4/8/12/16/24 |
| **主操作不突出** | 用户找不到"开始" | 一个界面一个 primaryBtn |
| **大列表全量加载** | 数据多了卡顿 | 规划虚拟化（QTableView+model 或限制行数） |
| **忘记空/错/加载态** | 界面"一片空白"或报错裸奔 | 三种状态都要画 |
| **中文硬编码** | 违反 string-extraction-gate | 一律进 strings_gui.py 常量 |
| **主线程阻塞** | 界面假死、切 Tab 卡 | 后台一律 QThread + pyqtSignal |
| **主题切换不跟随** | 切亮色后某处仍是暗色值 | 截图对比 + 不硬编码颜色 |
